## Known overlap and consolidation decisions

### Live E2E vs Live Repository Gate

The older `live-e2e.yml` duplicated the authoritative real-repository path. Its functional and integrity coverage is now represented by `live-repository-gate.yml` and the complementary `live-output-quality.yml`, so the standalone workflow was removed.

### Agent Contract Integrity vs Live Repository Gate

The former standalone contract workflow's persisted-contract MCP equality, tamper, plan-mismatch, stale-prepared-HEAD, and final-verification scenarios are now executed inside `live-repository-gate.yml`, together with broader repository binding, evidence determinism, MCP, REST, and immutability coverage. The standalone workflow was therefore removed.

### Live Output Quality vs Live Repository Gate

These remain intentionally complementary: the release gate proves functional/integrity behavior, while output quality captures and parses actual command/REST/MCP output and checks for stale CodeContext leakage and malformed JSON.
