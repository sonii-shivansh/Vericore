## Known overlap

### Live E2E vs Live Repository Gate

Both build Vericore, clone a real repository, exercise analysis/architecture/impact/evolution/context/Repo-QA/planning/verification and REST. The release gate already includes semantic-evidence-graph, contract-tamper, source-mutation, MCP and repository-immutability assertions. The older `live-e2e.yml` therefore has substantial duplicate coverage.

### Agent Contract Integrity vs Live Repository Gate

Both exercise prepare/verify and contract tampering. The standalone workflow has additional persisted-contract MCP equality, plan-mismatch and stale-prepared-HEAD scenarios. Those unique scenarios must be moved into the authoritative release gate before the standalone workflow is removed.

### Live Output Quality vs Live Repository Gate

These are intentionally complementary: the release gate proves functional/integrity behavior, while output quality captures and parses actual command/REST/MCP output and checks for stale CodeContext leakage and malformed JSON. They should remain separate reusable gates rather than being duplicated line-for-line.
