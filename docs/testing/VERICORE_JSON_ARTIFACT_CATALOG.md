# Vericore JSON Artifact Catalog & Specification

**Specification Version:** 1.0  
**Status:** Authoritative Product Catalog  
**Audited Against:** `cli-standardization` at commit `d0fe8302bc95657f8ee7e46de0f5b75afac38f5c`

---

## 1. Overview & Dual-Model Architecture

Vericore distinguishes clearly between two separate classes of JSON:

1. **Command Result Envelope (`CommandEnvelope<T>`):** The universal machine-readable response emitted to `stdout` (or written to `--output <file>`) when `--format json` or `--json` is requested for any CLI command.
2. **Domain Artifacts:** Persistent, structured engineering data generated by Vericore engines during repository discovery, analysis, planning, and verification, designed to be consumed by downstream commands and CI/CD pipelines.

---

## 2. Universal Command Result Envelope (`CommandEnvelope<T>`)

Every standard Vericore CLI command in JSON mode (`--format json` or `--json`) emits a `CommandEnvelope<T>` JSON object.

### Schema Specification
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion` (String): Schema version, currently `"1.0"`.
  - `command` (String): Exact command name executed (e.g. `"analyze"`, `"impact"`, `"verify"`).
  - `status` (String): Result status (`"PASS"`, `"SUCCESS"`, `"FAIL"`, `"WARNING"`, `"REVIEW_REQUIRED"`, `"NO_CHANGES"`, `"NO_FINDINGS"`, `"ALREADY_INITIALIZED"`, `"ERROR"`).
  - `summary` (String): Concise, single-line human-understandable summary of execution.
  - `findings` (Array of EnvelopeFinding): List of discrete findings (`level`, `message`, `ruleId`, `path`).
  - `recommendations` (Array of EnvelopeRecommendation): Actionable guidance (`priority`, `title`, `action`, `evidencePaths`).
  - `artifacts` (Array of EnvelopeArtifact): Referenced generated artifacts (`kind`, `path`).
  - `execution` (ExecutionInfo): Process status and execution metrics (`exitCode`).
- **Optional Fields:**
  - `repository` (RepositoryInfo): Repository identity (`name`, `path`).
  - `data` (T): Domain-specific command payload object.
  - `nextStep` (String): Suggested follow-up command or action.

### Example Envelope
```json
{
  "schemaVersion": "1.0",
  "command": "verify",
  "status": "PASS",
  "summary": "Working tree verification against engineering plan and change contract",
  "repository": {
    "name": "sample-project",
    "path": "C:/projects/sample-project"
  },
  "data": {
    "valid": true,
    "status": "PASS",
    "reasons": []
  },
  "findings": [],
  "recommendations": [],
  "artifacts": [
    {
      "kind": "receipt",
      "path": "C:/projects/sample-project/output/verification-receipt.json"
    }
  ],
  "nextStep": null,
  "execution": {
    "exitCode": 0
  }
}
```

## 3. Persistent Domain Artifacts Inventory

### 3.1 Project Configuration (`.vericore.json`)
- **Producing Command:** `init` (also modified by user / editor)
- **Default Location:** `<repository-root>/.vericore.json`
- **Explicit Option:** Path passed to `init --path <dir>`
- **Schema Version:** Unversioned root config
- **Required Fields:** None (defaults applied if omitted)
- **Main Fields:**
  - `ai`: Object containing `enabled` (Boolean), `provider` (String), `model` (String), `apiKey` (String)
  - `scanner`: Excluded paths, file size limits
  - `architecture`: Layer definitions, forbidden dependencies
- **Downstream Consumers:** All commands (`ConfigLoader.loadForRepository`)
- **Overwrite Rules:** `init` fails if already present unless `--force` is specified.

---

### 3.2 Analysis Snapshot (`output/analysis-snapshot.json`)
- **Producing Command:** `analyze`, `scan`
- **Default Location:** `<repository-root>/output/analysis-snapshot.json`
- **Explicit Option:** None (canonical repository analysis location)
- **Schema Version:** `com.vericore.core.intelligence.ANALYSIS_SCHEMA_VERSION` (`"1.0"`)
- **Required Fields:**
  - `schemaVersion` (String): `"1.0"`
  - `repository` (RepositorySnapshot): `path`, `analyzedAtEpochMillis`, `languages`, `repositoryCommit`
  - `metrics` (AnalysisMetrics): `totalFiles`, `totalNodes`, `totalEdges`, `parseFailures`, `cycleDetected`
  - `architecture` (ArchitectureSnapshot): `packageCount`, `crossPackageEdges`, `packages`
  - `hotspots` (List<HotspotNode>): Key centrality hotspots with `path`, `score`, `churn`, `dependents`
  - `graph` (SerializableGraph): Dependency graph vertices and edges
- **Downstream Consumers:** `inspect`, `evidence-graph`, `reality`, `recommendations`, `report`, `review`
- **Overwrite Rules:** Safely overwritten by subsequent `vericore analyze` executions.

---

### 3.3 Engineering Risks (`output/engineering-risks.json`)
- **Producing Command:** `analyze`
- **Default Location:** `<repository-root>/output/engineering-risks.json`
- **Schema Version:** Unversioned list
- **Main Data Structure:** Array of `EngineeringRiskItem` (`path`, `level`, `score`, `reasons`)
- **Downstream Consumers:** `inspect`, `recommendations`, HTML report

---

### 3.4 Change Impact Report (`output/change-impact.json`)
- **Producing Command:** `impact`
- **Default Location:** `<repository-root>/output/change-impact.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `changedPaths` (List<String>): Normalized list of changed file paths
  - `nodes` (List<ImpactNode>): Traverse reverse-dependencies and candidate test files
  - `summary` (ImpactSummary): `changedFiles`, `impactedFiles`, `impactedPackages`, `crossPackageImpacts`, `testCandidates`, `maxDepth`
  - `testCandidates` (List<String>): Explicit list of test candidate file paths
- **Downstream Consumers:** CI test selection, engineering planning (`plan`), developer review

---

### 3.5 Component Inspection (`output/inspection.json`)
- **Producing Command:** `inspect`
- **Default Location:** `<repository-root>/output/inspection.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `repository`: Repository root path
  - `analyzedAtEpochMillis`: Timestamp
  - `languages`: Detected languages
  - `metrics`: Files, nodes, edges, parse failures, cycles, packages, crossPackageEdges
  - `hotspots`: Top 5 hotspot nodes
  - `highRiskFiles`: Count of high/critical risk files
  - `criticalRiskFiles`: Count of critical risk files
  - `recommendations`: Top 5 recommendations
- **Downstream Consumers:** Architecture audits, developer inspection dashboards

---

### 3.6 Architecture Intelligence Report (`output/architecture.json`)
- **Producing Command:** `architecture`
- **Default Location:** `<repository-root>/output/architecture.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `summary`: `filesAnalyzed`, `dependencyEdges`, `findings`, `cycles`, `crossLayerDependencies`, `highCouplingFiles`
  - `findings`: List of `ArchitectureFinding` (`ruleId`, `severity`, `source`, `target`, `evidence`)
  - `cycles`: List of dependency cycles (arrays of node names)
- **Downstream Consumers:** `architecture-drift` (acts as baseline), architecture verification

---

### 3.7 Architecture Drift (`output/architecture-drift.json`)
- **Producing Command:** `architecture-drift`
- **Default Location:** `<repository-root>/output/architecture-drift.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `summary`: `addedFindings`, `removedFindings`, `newCycles`, `resolvedCycles`, `addedEdges`, `removedEdges`
  - `changes`: List of `DriftChange` (`type`, `key`, `detail`)
- **Downstream Consumers:** CI quality gates, PR reviews

---

### 3.8 Architecture Contract Result (`output/architecture-contract.json`)
- **Producing Command:** `architecture-contract`
- **Default Location:** `<repository-root>/output/architecture-contract.json`
- **Explicit Option:** `--output <file>`, `--record <file>` for decision history
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `passed` (Boolean): Whether all contract limits were satisfied
  - `violations` (List<ArchitectureContractViolation>): `ruleId`, `severity`, `message`, `source`, `target`
  - `checked` (ArchitectureContract): Contract definition evaluated
- **Downstream Consumers:** CI policy enforcement (exits with 1 when `passed == false`)

---

### 3.9 Engineering Context Snapshot (`output/engineering-context.json`)
- **Producing Command:** `context-snapshot`
- **Default Location:** `<repository-root>/output/engineering-context.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `repositoryCommit`: Git commit hash at capture time
  - `files`: List of `ContextFile` (`path`, `sha256`, `sizeBytes`)
  - `totalFiles`: Integer count of files
  - `totalBytes`: Total file bytes
  - `dirty`: Boolean indicating working tree modification state
  - `snapshotDigest`: Cryptographic SHA-256 digest over the sorted file manifest
- **Downstream Consumers:** `context-diff`, change preparation (`prepare`), candidate baseline verification

---

### 3.10 Engineering Context Diff (`output/engineering-context-diff.json`)
- **Producing Command:** `context-diff`
- **Default Location:** `<repository-root>/output/engineering-context-diff.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `beforeCommit`: Baseline commit SHA
  - `afterCommit`: Target commit SHA
  - `changes`: List of `FileChange` (`type` = ADDED/REMOVED/MODIFIED, `path`, `oldSha`, `newSha`)
  - `summary`: Added, removed, modified, and unchanged file counts
- **Downstream Consumers:** CI audit, release diffs

---

### 3.11 Semantic Evidence Graph (`output/semantic-evidence-graph.json`)
- **Producing Command:** `evidence-graph`
- **Default Location:** `<repository-root>/output/semantic-evidence-graph.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `com.vericore.core.evidence.SemanticEvidenceGraphArtifact.SCHEMA_VERSION` (`"1.0"`)
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `repositoryId`: Repository root path
  - `observedCommit`: Git commit hash
  - `digest`: SHA-256 digest over the graph representation
  - `nodeCount`: Integer node count
  - `edgeCount`: Integer edge count
  - `nodes`: List of `SemanticEvidenceNode` (`id`, `kind`, `label`, `file`, `attributes`)
  - `edges`: List of `SemanticEvidenceEdge` (`sourceId`, `targetId`, `relationship`, `weight`)
- **Downstream Consumers:** AI grounding, QA retriever, reality verification

---

### 3.12 Engineering Reality Artifact (`output/engineering-reality.json`)
- **Producing Command:** `reality`
- **Default Location:** `<repository-root>/output/engineering-reality.json`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `repository`: Repository root
  - `commit`: Current commit
  - `observedFacts`: Validated facts across scanner, git, graph, and architecture
  - `digest`: SHA-256 reality digest
- **Downstream Consumers:** AI agent safety grounding, autonomous developer agents

---

### 3.13 PR Intelligence Report (`output/pr-intelligence.json`)
- **Producing Command:** `pr-intelligence`
- **Default Location:** `<repository-root>/output/pr-intelligence.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `changeSummary`: `filesChanged`, `additions`, `deletions`
  - `impactedFiles`: Count of reverse-dependent files
  - `impactedPackages`: Count of impacted packages
  - `crossPackageImpacts`: Count of cross-package boundaries crossed
  - `testCandidates`: Recommended test files
  - `findings`: List of `PRFinding` (`ruleId`, `severity`, `paths`, `reason`)
  - `aggregateSeverity`: Highest finding severity (`NONE`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`)
- **Downstream Consumers:** Code review automation, GitHub Actions PR checks

---

### 3.14 Code Review Report (`output/review.json`)
- **Producing Command:** `review`
- **Default Location:** `<repository-root>/output/review.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** `"1.0"`
- **Main Fields:**
  - `deterministic`: Full `PRIntelligenceResult`
  - `groundedAi`: Optional `GroundedAIResponse` with AI narrative and citations when `--ai` is passed
- **Downstream Consumers:** Pull request reviewers, CI review gates

---

### 3.15 Engineering Recommendations (`output/recommendations.json`)
- **Producing Command:** `recommendations`
- **Default Location:** `<repository-root>/output/recommendations.json`
- **Explicit Option:** `--output <file>`
- **Schema Version:** List of `EngineeringRecommendation`
- **Main Fields per Item:**
  - `id`: Recommendation identifier (e.g. `"BASELINE_HEALTHY"`, `"HIGH_CENTRALITY_HOTSPOT"`)
  - `priority`: `"CRITICAL"`, `"HIGH"`, `"MEDIUM"`, `"LOW"`
  - `title`: Short title
  - `reason`: Analytical justification
  - `action`: Concrete recommended developer action
  - `evidencePaths`: Array of relative file paths supporting the recommendation
- **Downstream Consumers:** Technical debt trackers, backlog planners

---

### 3.16 Engineering Plan (`output/engineering-plan.json`)
- **Producing Command:** `plan`, `prepare`
- **Default Location:** `<repository-root>/output/engineering-plan.json`
- **Explicit Option:** `--output <file>` in `plan`; `--plan-output <file>` in `prepare`
- **Schema Version:** `"1.0"`
- **Required Fields:**
  - `schemaVersion`: `"1.0"`
  - `changeSummary`: Description of intended engineering goal
  - `riskLevel`: Assessment of risk (`"LOW"`, `"MEDIUM"`, `"HIGH"`, `"CRITICAL"`)
  - `plannedPaths`: Bounded list of files authorized for modification
  - `affectedComponents`: Upstream/downstream dependent components
  - `contractFingerprint`: Cryptographic binding to change contract
  - `specification`: Structured change requirements (required/forbidden behaviors, invariants, acceptance criteria)
- **Downstream Consumers:** `prepare`, `verify`, autonomous coding agents

---

### 3.17 Agent Change Contract (`output/agent-change-contract.json`)
- **Producing Command:** `prepare`
- **Default Location:** `<repository-root>/output/agent-change-contract.json`
- **Explicit Option:** `--contract-output <file>`
- **Schema Version:** `"3.0"`
- **Required Fields:**
  - `schemaVersion`: `"3.0"`
  - `repository`: Repository root path
  - `preparedHead`: Git commit SHA at preparation time
  - `plannedPaths`: Exact list of authorized modification paths
  - `baselineManifest`: Full file hash manifest of candidate repository state at prepare time
  - `fingerprint`: HMAC/SHA-256 tamper-proof contract fingerprint
- **Downstream Consumers:** `verify` (enforces strict candidate baseline check and rejects out-of-scope modifications)

---

### 3.18 Verification Receipt (`output/verification-receipt.json`)
- **Producing Command:** `verify`
- **Default Location:** `<repository-root>/output/verification-receipt.json`
- **Schema Version:** `"1.3"`
- **Required Fields:**
  - `schemaVersion`: `"1.3"`
  - `status`: Verification outcome (`"PASS"`, `"FAIL"`, `"REVIEW_REQUIRED"`)
  - `timestampEpochMillis`: Execution timestamp
  - `verifiedHead`: Commit or working tree state hash
  - `contractFingerprint`: Evaluated contract fingerprint
  - `baselineDigestValid`: Boolean indicating whether un-planned files remained bit-for-bit unchanged
  - `unplannedDriftPaths`: Array of file paths changed outside authorized `plannedPaths`
  - `specificationEvaluation`: Status and detail of requirement criteria evaluation
- **Downstream Consumers:** CI safety gates, automated merge bots

## 4. Special Integration Formats

### 4.1 MCP JSON-RPC 2.0 (`vericore mcp`)
- **Transport:** Standard I/O (stdio)
- **Protocol:** Model Context Protocol (JSON-RPC 2.0)
- **Rule:** Standard output is strictly reserved for valid JSON-RPC frames (`{"jsonrpc":"2.0", ...}`). Human text, logs, or diagnostic output must never be printed to standard output.

### 4.2 MCP Client Configuration (`.mcp.json`)
- **Producing Command:** `mcp-config`
- **Default Location:** `<repository-root>/.mcp.json`
- **Format:**
```json
{
  "mcpServers": {
    "vericore": {
      "command": "C:/tools/vericore/bin/vericore.bat",
      "args": ["mcp"]
    }
  }
}
```

### 4.3 REST Server HTTP API (`vericore server`)
- **Transport:** HTTP / TCP
- **Endpoints:**
  - `GET /health` -> `{"status":"UP","version":"2.0.0"}`
  - `GET /api/v1/context` -> Engineering context snapshot payload
- **Protocol:** Standard HTTP with JSON payload and proper HTTP status codes (200, 400, 404, 500).
