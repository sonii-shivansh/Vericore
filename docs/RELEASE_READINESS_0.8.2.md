## Release scope

This patch release contains the post-`0.8.1` audit remediation and release hardening work already present on the release branch.

### Functional remediation

- Diagnostic failures use meaningful non-zero exit semantics.
- Validation failures use controlled application/CLI errors rather than raw stack traces.
- Repository-QA evidence retains concrete dependency/dependent paths.
- Architecture dependency edges are persisted deterministically.
- Architecture drift detects explicit `EDGE_ADDED` and `EDGE_REMOVED` changes.
- Organization-analysis hotspots serialize as explicit `{file, score}` objects.
- Regression coverage protects the historical `0.8.1` audit findings.

### Machine-readable contract changes

- Organization-analysis hotspot output uses objects with explicit `file` and `score` fields instead of Kotlin `Pair` serialization.
- Architecture Intelligence artifacts use schema `1.1` and persist `dependencyEdges` so edge-level drift is deterministic.
- Historical schema `1.0` references remain historical where they describe older artifacts or fixtures.

### Release engineering

- Application and Gradle version contracts are aligned to `0.8.2`.
- Linux x64, Windows x64, macOS x64, and macOS ARM64 packaging is required.
- Bundled Java 21 runtime verification is required for packaged artifacts.
- SHA-256 checksums are generated by the release workflow.
- The exact candidate must pass final release certification before packaging/publication.
